# LAYA Breakfast Local v2.9.4 — โน้ตบุ๊กเครื่องเดียว

ไม่ใช้ Firebase ไม่ต้องมีบัญชีหรือชำระค่าฐานข้อมูล ข้อมูลเก็บใน IndexedDB ของเบราว์เซอร์บนเครื่องนี้
รองรับการนำเข้า PDF / Excel / CSV ตรวจ RO/RB ห้องนอกตึกถูกตัดออก รับเงิน RO / รอชำระ และรายงานย้อนหลังเหมือนรุ่นเดิม
หน้ารับลูกค้ามีแป้นเลขห้องและโหมดรับลูกค้า

## เริ่มใช้บน GitHub Pages
1. แตก ZIP เปิดโฟลเดอร์ laya-breakfast-local
2. อัปโหลดไฟล์ภายในให้ index.html อยู่ที่ root ของ repository ตามเดิม
3. เปิด Settings > Pages ใช้ branch main และ /(root)
4. เปิด URL ด้วย Chrome หรือ Edge บนโน้ตบุ๊กเครื่องที่จะใช้จริง ระบบเปิดข้อมูลในเครื่องให้อัตโนมัติ
5. รอให้แถบด้านบนขึ้น “พร้อมเปิดใช้งานออฟไลน์บนเครื่องนี้” ก่อนตัดอินเทอร์เน็ต
6. นำเข้าไฟล์รายงานของวันนี้ เลือก RO/RB หรือแก้จำนวนที่ต้องการ แล้วกดยืนยันนำเข้าได้ทันที ไม่ต้องกรอกคอมเมนต์
7. ผู้ดูแลตั้งค่าโฟลเดอร์สำรองครั้งแรกในส่วน “ข้อมูลของโน้ตบุ๊กเครื่องนี้” ใต้หน้านำเข้า/รายงาน แล้วอนุญาตเขียนไฟล์ ระบบสำรองอัตโนมัติหลังข้อมูลเปลี่ยน

GitHub ใช้ส่งไฟล์เว็บครั้งแรกและเมื่ออัปเดต ข้อมูลแขกไม่ถูกส่งขึ้น GitHub หรือ Firebase
อย่าอัปโหลด PDF รายงานจริงหรือไฟล์สำรอง JSON เข้า repository
หากไม่ต้องการใช้ GitHub ให้เปิดผ่านเว็บเซิร์ฟเวอร์ในเครื่อง เช่น Python http.server เมื่อมี Python แล้ว
ห้ามดับเบิลคลิก index.html เพื่อใช้ผ่าน file:// เพราะ modules และออฟไลน์ต้องใช้ HTTPS หรือ localhost
สามารถติดตั้งเป็นแอปจาก Chrome/Edge หลังเปิด URL GitHub Pages
ใช้โปรไฟล์และ URL เดิมทุกครั้ง การย้าย URL/เปลี่ยนเบราว์เซอร์จะเป็นพื้นที่ข้อมูลคนละชุด

## เก็บข้อมูลและสำรอง
บันทึกรายชื่อ จำนวนเข้าทาน ประวัติ ยอดรับเงิน และกฎ Rate Code ลง IndexedDB
ปิดแท็บ/ปิดเครื่องแล้วเปิดใหม่ ข้อมูลยังอยู่ในโปรไฟล์เดิม
สำรอง JSON รวมทุกวันและกฎราคา เก็บไฟล์ต้นฉบับ PDF ไว้ต่างหาก แอปไม่เก็บ PDF ต้นฉบับ
รายงาน CSV สำหรับ Excel เป็นรายงานอ่านได้ ไม่ใช่ไฟล์กู้คืนทั้งหมด
ระบบสร้างสำเนาอัตโนมัติใน IndexedDB ทุกครั้งที่เขียนข้อมูล
เมื่อตั้งค่าโฟลเดอร์แล้ว ระบบเขียน LAYA_Backup_Automatic.json รวมทุกวันให้อัตโนมัติภายในประมาณครึ่งวินาทีหลังข้อมูลเปลี่ยน
ไฟล์ล่าสุดถูกแทนที่เมื่อข้อมูลเปลี่ยน ส่วนไฟล์ก่อนล้าง/ลบ/กู้คืนใช้ชื่อแยกและไม่แทนที่ไฟล์ก่อนหน้า
หากยังไม่ได้ตั้งค่าโฟลเดอร์หรือสิทธิ์หมด จะมีเฉพาะสำเนาในเบราว์เซอร์ และดาวน์โหลดไฟล์ก่อนล้าง/ลบ/กู้คืนแทน
การล้างข้อมูลเว็บไซต์จะลบทั้งฐานข้อมูลและสำเนาในเบราว์เซอร์ จึงควรตั้งค่าโฟลเดอร์ไฟล์จริง
หากสิทธิ์โฟลเดอร์หมด ระบบแสดงสถานะให้ผู้ดูแลอนุญาตใหม่ ไม่หยุดรับลูกค้า

## กู้คืน
เลื่อนลงส่วน “ข้อมูลของโน้ตบุ๊กเครื่องนี้” เลือกไฟล์ JSON จากโฟลเดอร์สำรองหรือ Downloads
ระบบตรวจรูปแบบ เช็กความครบถ้วน และแสดงจำนวนวัน/รายการก่อนยืนยัน
การกู้คืนแทนที่ข้อมูลทั้งหมด ไม่รวมกับข้อมูลเดิม
ก่อนแทนที่จะจัดเตรียมไฟล์ LAYA_Before_Restore ให้ และเก็บสำเนาก่อนกู้คืนไว้ภายในฐานข้อมูล
หากต้องการย้อนกลับ ให้กู้จากไฟล์ LAYA_Before_Restore ที่ดาวน์โหลดไว้
ไฟล์ที่ไม่ครบ/ตรวจสอบไม่ผ่านจะไม่เปลี่ยนฐานข้อมูล

## การใช้งานประจำวัน
ตึก 1=A, 2=B, 3=C, 5=D; 9xxx/PM/POS ไม่ถูกนับ
PDF แบบข้อความตามรายงานที่ทดสอบเท่านั้น ไม่รองรับ PDF สแกนเป็นภาพ
ห้อง REVIEW ให้เลือก RO/RB ในหน้านำเข้าก่อนบันทึกเข้าทาน โดยไม่ต้องใส่คอมเมนต์ RO เลือกชำระแล้วหรือเข้าทานแล้วรอชำระ RB รวมอาหารเช้า
เลือกจำนวนคนที่มารอบนี้ จำนวนเริ่มต้น 1 คน กรอกเกินจำนวนผู้พักตามรายงานได้
ขึ้นวันใหม่ตามเวลาไทย ต้องนำเข้ารายงานใหม่ ประวัติย้อนหลังยังอยู่
หากกดซ้ำ/เปิดหลายแท็บในเบราว์เซอร์เดียวกัน ระบบบันทึกเป็น transaction และไม่บันทึก event ID เดิมซ้ำ
รุ่นนี้ไม่ซิงก์ข้อมูลระหว่างเครื่อง และไม่มีระบบบัญชีหรือแยกสิทธิ์พนักงาน ทุกคนที่เปิดได้มีสิทธิ์ผู้ดูแล

## ดูแลข้อมูลในเครื่อง
ใช้ Chrome/Edge แบบปกติ ไม่ใช้โหมดไม่ระบุตัวตน
อย่าล้างข้อมูลเว็บไซต์หรือโปรไฟล์ ใช้ไฟล์สำรองกู้คืนหากเปลี่ยนเครื่องหรือข้อมูลหาย
ตั้งวันเวลาเครื่องให้ถูกต้อง เพราะรุ่นออฟไลน์อ้างอิงเวลาของโน้ตบุ๊ก
แอปขอพื้นที่เก็บข้อมูลถาวรจากเบราว์เซอร์ แต่เบราว์เซอร์อาจไม่อนุญาต จึงต้องสำรองทุกวัน
โหมดทดลองยังแยกจากข้อมูลจริงและข้อมูลทดลองไม่รวมในสำรอง
รุ่นนี้ไม่ดึงประวัติจาก Firebase อัตโนมัติ

## อัปเดตรุ่น
เปลี่ยนไฟล์เว็บที่ URL เดิม ไม่ล้างข้อมูลเว็บไซต์ ปิดแท็บเก่าหลังอัปเดตแล้วเปิดใหม่
service worker เก็บไฟล์รุ่นปัจจุบันไว้ เมื่อมีรุ่นใหม่ต้องอัปเดตหมายเลข cache ใน sw.js ด้วย

## รับลูกค้าด้วย Enter (v2.2)
พิมพ์เลขห้องแล้ว Enter หรือกดปุ่ม Enter บนแป้นหน้าจอ
- RB เปิดหน้าต่าง “มาทานกี่คน?” ช่องจำนวนโฟกัสพร้อมพิมพ์ พิมพ์จำนวนแล้ว Enter อีกครั้งเพื่อบันทึก
- จำนวนเริ่มต้น 1 คน เลือกจำนวนที่หน้าเดิมก่อนได้ และกรอกเกินจำนวนผู้พักคงเหลือได้
- RO เปิดหน้าต่างรับชำระเงินตามเดิม เลือกจำนวน ยอด แล้วเลือกชำระแล้วหรือรอชำระ
- ยกเลิกหรือ Esc ปิดหน้าต่างทั้ง RB/RO โดยไม่บันทึก
- กรอกครบ 4 หลักอย่างเดียวแสดงข้อมูล ยังไม่บันทึก
- บันทึกสำเร็จล้างเลขห้องและคืนโฟกัสให้พิมพ์ห้องถัดไป
อัปเดตออนไลน์หนึ่งครั้งแล้วปิดแท็บแอปทั้งหมด เปิด URL เดิมใหม่เพื่อรับไฟล์ออฟไลน์รุ่นใหม่ ข้อมูลเดิมไม่ต้องนำเข้าใหม่

## รายงานแยก Phase (v2.3)
หน้า “ประวัติ / รายงาน” เลือกวันที่ แล้วกด “Excel แยก 2 Phase”
ไฟล์เดียวมี 2 ชีต Phase 1 (ตึก A/B/C หรือ 1/2/3) และ Phase 2 (ตึก D หรือ 5)
แต่ละชีตมีผู้พักตามรายงาน ห้องที่เข้าทาน ยอด RB/RO ยอดรับเงิน และรายละเอียดแต่ละรายการ
ปุ่ม “พิมพ์สรุป 2 ใบ” เปิดหน้าพิมพ์ A4 แยกคนละหน้า มีสรุปรายตึกและวิธีชำระเงิน
เลือก Save as PDF ในหน้าพิมพ์ได้ รายละเอียดรายห้องดูใน Excel
รายงาน 2 Phase ใช้ทุกตึกของวันที่เลือก ไม่ขึ้นกับตัวกรองตึกในตารางรายการ
ปุ่ม CSV ตามตัวกรองยังส่งออกเฉพาะรายการที่กรองอยู่ได้
ทุกยอดเข้าทานมาจากประวัติที่บันทึกแล้ว จำนวนผู้พักมาจากรายงานนำเข้าของวันนั้น
หากมีการนำเข้ารายชื่อแทนที่ จำนวนผู้พักใช้ฉบับล่าสุด แต่ประวัติที่บันทึกแล้วคงอยู่

## นำเข้าโดยไม่ต้องกรอกผลตรวจสอบจาก FO (v2.4)
ไม่มีช่องคอมเมนต์รายห้อง แก้สถานะหรือจำนวนแล้วกดยืนยันนำเข้าได้เลย
ระบบบันทึกผู้แก้ไขให้อัตโนมัติ กำหนด Rate Code ครั้งเดียวเพื่อใช้กับทุกห้องที่มีรหัสเดียวกันได้
สิทธิ์ที่อ่านจากรายงานไม่ชัดเจนยังแสดงรอตรวจสอบ ให้เลือก RO/RB โดยไม่ต้องกรอกเหตุผล

## หน้ารับลูกค้าพอดีจอโน้ตบุ๊ก (v2.5)
หน้ารับลูกค้าปรับขนาดตามความสูงหน้าจอโดยอัตโนมัติ ลดช่องว่างและแป้นตัวเลขให้กระชับ
หน้าต่างจำนวนแขก RB และรับเงิน RO ปรับให้พอดีหน้าจอด้วย
แถบยอดรวม ช่องเลขห้อง ข้อมูลแขก และปุ่มใช้งานอยู่ในหน้าเดียว
ส่วนกู้คืนข้อมูลและการตั้งค่าโฟลเดอร์อยู่ใต้หน้านำเข้ารายวัน/ประวัติ หน้ารับลูกค้ามีเพียงสถานะสำรอง ไม่มีปุ่มสำรอง
บนมือถือยังใช้รูปแบบแนวตั้งเพื่อให้ช่องกรอกและปุ่มอ่านง่าย

## ล้างยอด/ลบเฉพาะวัน (v2.6)
หน้า “ประวัติ / รายงาน” เลือกวันที่ แล้วเปิด “จัดการข้อมูลวันที่เลือก”
ล้างยอดเข้าทาน: เก็บรายชื่อ/สิทธิ์/จำนวนผู้พักไว้ ล้างประวัติเข้าทานและยอดรับเงินเพื่อเริ่มนับใหม่
ลบข้อมูลวันที่เลือกทั้งหมด: ลบทั้งรายชื่อและรายการเข้าทานของวันนั้น ต้องนำเข้ารายงานใหม่ก่อนใช้งานวันนั้น
ทั้งสองแบบแสดงวันที่และให้ยืนยันก่อนดำเนินการ วันอื่นไม่เปลี่ยน
ก่อนล้าง/ลบ ระบบเขียนไฟล์สำรองแยกในโฟลเดอร์ หากไม่มีสิทธิ์โฟลเดอร์จะดาวน์โหลดแทน
ระบบเก็บสำเนาก่อนล้าง/ลบในเบราว์เซอร์ด้วย และไม่ล้างหากข้อมูลเปลี่ยนระหว่างสำรอง
ไม่ต้องล้างข้อมูลเพื่อใช้วันถัดไป ระบบแยกวันอยู่แล้ว

Chrome/Edge บน Windows: เลือกโฟลเดอร์ครั้งแรกด้วยปุ่ม “ตั้งค่าโฟลเดอร์สำรองอัตโนมัติ”
หากเบราว์เซอร์มีตัวเลือกอนุญาตทุกครั้ง ให้เลือกเพื่อให้ใช้โฟลเดอร์ต่อเนื่อง
เบราว์เซอร์อาจขออนุญาตใหม่ตามการตั้งค่า ผู้ดูแลกดปุ่มเดิมเพื่ออนุญาตอีกครั้ง

## อ่าน RO/RB และบรรทัดต่อเนื่องจาก PDF (v2.7)
รองรับ 3RB, 2RB, 1 RB, 2RO และตัวอักษร R B / R O ที่แยกเป็นชิ้นข้อความใน PDF
อ่านชื่อที่ขึ้นบรรทัดใหม่ และเก็บข้อความต่อเนื่องของห้องจากหน้าถัดไปจนพบห้องใหม่
ในตารางนำเข้า กด “ดูข้อความทุกบรรทัดที่อ่านได้” เพื่อดูข้อความของห้องและเลขหน้า
v2.9 รวมทุกแถวของห้องซ้ำ ใช้ยอดที่มากกว่าระหว่าง Adl.+Chl. รวม กับจำนวนแถวรายชื่อที่ไม่ซ้ำ พร้อมแสดงยอดทั้งสองให้ตรวจและแก้จำนวนได้ แถวหลักที่มีจำนวนรวมอยู่แล้วไม่ถูกบวกกับผู้ร่วมพัก 0 คนซ้ำ
จำนวนคนยังอิง Adl.+Chl. ไม่ใช้เลขในหมายเหตุมาแทนจำนวนคนโดยอัตโนมัติ
สิทธิ์ขัดกัน/ไม่มีหลักฐานยังต้องเลือกสถานะเอง ไม่ต้องกรอกคอมเมนต์ FO
หลังอัปเดต ให้นำเข้า PDF ชุดเดิมอีกครั้งเพื่ออ่านใหม่ ระบบเก็บยอดเข้าทานเดิมไว้
PDF สแกนเป็นภาพยังไม่รองรับ และระบบยังตรวจยอดรวมท้ายรายงานก่อนบันทึก

## RO เข้าทานแล้วรอชำระ (v2.8)
กรอกเลขห้อง RO + Enter ระบุจำนวนแขกและยอดอาหารเช้ารวม
- ชำระแล้ว · เข้าทาน: เลือกวิธีรับเงิน แล้วกดปุ่มเพื่อยืนยันว่ารับเงินจริง นับแขกพร้อมยอดรับเงิน
- เข้าทานแล้ว · รอชำระ: ไม่ต้องติ๊กรับเงิน นับแขกแต่ยอดรับเงินเป็นศูนย์ เก็บยอดค้างแยก
- ไม่เข้าทาน · ยกเลิก: ไม่เพิ่มยอดหรือรายได้
ใช้รอชำระเมื่อแขกเข้าทานจริงแล้วหรือได้รับอนุญาตให้จ่ายภายหลัง
กด RO รอชำระที่หน้ารับลูกค้า หรือเปิดประวัติของวันที่บริการ เพื่อรับเงินรายการเดิม
รับเงินภายหลังต้องรับเต็มยอด เลือกวิธีและติ๊กรับเงินครบ ไม่เพิ่มจำนวนแขกซ้ำ
รายงานแยกเงินรับแล้วและยอดค้าง พร้อมสถานะและเวลารับเงินใน Excel/CSV
ยอดรับเงินภายหลังปรับในรายงานของวันบริการเดิม บันทึก settledAt/settledBy ไว้ในไฟล์สำรอง
รองรับรับเงินของวันที่ย้อนหลัง ยังไม่รองรับแบ่งจ่ายบางส่วน
ไฟล์สำรองใหม่ที่มีรายการรอชำระต้องใช้ v2.8 ขึ้นไปในการกู้คืน ไฟล์เก่ายังกู้คืนใน v2.8 ได้


v2.9.1 เอาช่องติ๊กได้รับชำระเงินเรียบร้อยแล้วออก ปุ่มชำระแล้ว · เข้าทานยืนยันรับเงินโดยตรง ยอดเงินและจำนวนยังต้องถูกต้องตามเงื่อนไขเดิม


v2.9.2 ปุ่มราคา 590 / 350 / 250 บาทต่อคนในหน้ารับชำระ RO คูณจำนวนแขกอัตโนมัติ เปลี่ยนจำนวนแล้วคำนวณใหม่ กรอกยอดรวมเองได้สำหรับราคาผสม เมื่อแก้ยอดเองจะเลิกคำนวณอัตโนมัติจนเลือกปุ่มราคาอีกครั้ง กดราคาไม่บันทึกข้อมูล ต้องกดชำระแล้วเข้าทานหรือรอชำระ


v2.9.3 จำนวนผู้พักในรายงานเป็นข้อมูลอ้างอิง ไม่จำกัดจำนวนเข้าทาน กรอกจำนวนเต็มบวกได้ เพิ่มได้เมื่อห้องเข้าทานครบแล้ว หน้ารับลูกค้าแสดงยอดเกินรายงาน รายงาน Phase 1/2 นับจำนวนเข้าทานจริง ยอดผู้พักต้นฉบับไม่เปลี่ยน เงื่อนไข RO/RB และยอดเงินเหมือนเดิม ไฟล์สำรองที่มีรายการเข้าทานเกิน 50 คนต่อครั้งต้องกู้คืนด้วย v2.9.3 ขึ้นไป


v2.9.4 ชื่อแขกในป๊อปอัป RB/RO ใหญ่และหนาขึ้น มีกรอบพื้นหลัง แสดงชื่อแยกบรรทัดและตัดบรรทัดชื่อยาวได้
