# LAYA Breakfast Local v2.2 — โน้ตบุ๊กเครื่องเดียว

ไม่ใช้ Firebase ไม่ต้องมีบัญชีหรือชำระค่าฐานข้อมูล ข้อมูลเก็บใน IndexedDB ของเบราว์เซอร์บนเครื่องนี้
รองรับการนำเข้า PDF / Excel / CSV ตรวจ RO/RB ห้องนอกตึกถูกตัดออก รับเงิน RO และรายงานย้อนหลังเหมือนรุ่นเดิม
หน้ารับลูกค้ามีแป้นเลขห้องและโหมดรับลูกค้า

## เริ่มใช้บน GitHub Pages
1. แตก ZIP เปิดโฟลเดอร์ laya-breakfast-local
2. อัปโหลดไฟล์ภายในให้ index.html อยู่ที่ root ของ repository ตามเดิม
3. เปิด Settings > Pages ใช้ branch main และ /(root)
4. เปิด URL ด้วย Chrome หรือ Edge บนโน้ตบุ๊กเครื่องที่จะใช้จริง ระบบเปิดข้อมูลในเครื่องให้อัตโนมัติ
5. รอให้แถบด้านบนขึ้น “พร้อมเปิดใช้งานออฟไลน์บนเครื่องนี้” ก่อนตัดอินเทอร์เน็ต
6. นำเข้าไฟล์รายงานของวันนี้ ตรวจสิทธิ์/จำนวนกับ FO แล้วรับลูกค้า
7. หลังจบอาหารเช้า กด “สำรองข้อมูล” ตรวจไฟล์ JSON ใน Downloads และคัดลอกเก็บอีกที่ เช่น USB

GitHub ใช้ส่งไฟล์เว็บครั้งแรกและเมื่ออัปเดต ข้อมูลแขกไม่ถูกส่งขึ้น GitHub หรือ Firebase
อย่าอัปโหลด PDF รายงานจริงหรือไฟล์สำรอง JSON เข้า repository
หากไม่ต้องการใช้ GitHub ให้เปิดผ่านเว็บเซิร์ฟเวอร์ในเครื่อง เช่น Python http.server เมื่อมี Python แล้ว
ห้ามดับเบิลคลิก index.html เพื่อใช้ผ่าน file:// เพราะ modules และออฟไลน์ต้องใช้ HTTPS หรือ localhost
สามารถติดตั้งเป็นแอปจาก Chrome/Edge หลังเปิด URL GitHub Pages
ใช้โปรไฟล์และ URL เดิมทุกครั้ง การย้าย URL/เปลี่ยนเบราว์เซอร์จะเป็นพื้นที่ข้อมูลคนละชุด

## เก็บข้อมูลและสำรอง
บันทึกรายชื่อ จำนวนเข้าทาน ประวัติ ยอดรับเงิน และกฎ Rate Code ลง IndexedDB
ปิดแท็บ/ปิดเครื่องแล้วเปิดใหม่ ข้อมูลยังอยู่ในโปรไฟล์เดิม
สำรอง JSON รวมทุกวันและกฎราคา เก็บไฟล์ต้นฉบับ PDF ไว้ต่างหาก แอปไม่เก็บ PDF ต้นฉบับ
รายงาน CSV สำหรับ Excel เป็นรายงานอ่านได้ ไม่ใช่ไฟล์กู้คืนทั้งหมด
การดาวน์โหลดสำรองคือจัดเตรียมไฟล์ เบราว์เซอร์ไม่สามารถยืนยันว่าได้คัดลอกไป USB แล้ว
แถบเตือนจะขึ้นเมื่อมีการเปลี่ยนข้อมูลหลังจัดเตรียมสำรองครั้งล่าสุด

## กู้คืน
เลื่อนลงส่วน “ข้อมูลของโน้ตบุ๊กเครื่องนี้” เลือกไฟล์ JSON จากปุ่มสำรอง
ระบบตรวจรูปแบบ เช็กความครบถ้วน และแสดงจำนวนวัน/รายการก่อนยืนยัน
การกู้คืนแทนที่ข้อมูลทั้งหมด ไม่รวมกับข้อมูลเดิม
ก่อนแทนที่จะจัดเตรียมไฟล์ LAYA_Before_Restore ให้ และเก็บสำเนาก่อนกู้คืนไว้ภายในฐานข้อมูล
หากต้องการย้อนกลับ ให้กู้จากไฟล์ LAYA_Before_Restore ที่ดาวน์โหลดไว้
ไฟล์ที่ไม่ครบ/ตรวจสอบไม่ผ่านจะไม่เปลี่ยนฐานข้อมูล

## การใช้งานประจำวัน
ตึก 1=A, 2=B, 3=C, 5=D; 9xxx/PM/POS ไม่ถูกนับ
PDF แบบข้อความตามรายงานที่ทดสอบเท่านั้น ไม่รองรับ PDF สแกนเป็นภาพ
ห้อง REVIEW ต้องยืนยันกับ FO ก่อนบันทึกเข้าทาน RO ต้องรับเงินก่อน RB รวมอาหารเช้า
เลือกจำนวนคนที่มารอบนี้ จำนวนเริ่มต้น 1 คน ไม่เกินจำนวนผู้พัก
ขึ้นวันใหม่ตามเวลาไทย ต้องนำเข้ารายงานใหม่ ประวัติย้อนหลังยังอยู่
หากกดซ้ำ/เปิดหลายแท็บในเบราว์เซอร์เดียวกัน ระบบบันทึกเป็น transaction เพื่อไม่ให้ยอดเกิน
รุ่นนี้ไม่ซิงก์ข้อมูลระหว่างเครื่อง และไม่มีระบบบัญชีหรือแยกสิทธิ์พนักงาน ทุกคนที่เปิดได้มีสิทธิ์ผู้ดูแล

## ดูแลข้อมูลในเครื่อง
ใช้ Chrome/Edge แบบปกติ ไม่ใช้โหมดไม่ระบุตัวตน
อย่าล้างข้อมูลเว็บไซต์หรือโปรไฟล์ ใช้ไฟล์สำรองกู้คืนหากเปลี่ยนเครื่องหรือข้อมูลหาย
ตั้งวันเวลาเครื่องให้ถูกต้อง เพราะรุ่นออฟไลน์อ้างอิงเวลาของโน้ตบุ๊ก
แอปขอพื้นที่เก็บข้อมูลถาวรจากเบราว์เซอร์ แต่เบราว์เซอร์อาจไม่อนุญาต จึงต้องสำรองทุกวัน
โหมดทดลองยังแยกจากข้อมูลจริงและข้อมูลทดลองไม่รวมในสำรอง
รุ่นนี้ไม่ดึงประวัติจาก Firebase อัตโนมัติ

## อัปเดตรุ่น
เปลี่ยนไฟล์เว็บที่ URL เดิม ไม่ล้างข้อมูลเว็บไซต์ ปิดแท็บเก่าหลังอัปเดตแล้วเปิดใหม่
service worker เก็บไฟล์รุ่นปัจจุบันไว้ เมื่อมีรุ่นใหม่ต้องอัปเดตหมายเลข cache ใน sw.js ด้วย

## รับลูกค้าด้วย Enter (v2.2)
พิมพ์เลขห้องแล้ว Enter หรือกดปุ่ม Enter บนแป้นหน้าจอ
- RB เปิดหน้าต่าง “มาทานกี่คน?” ช่องจำนวนโฟกัสพร้อมพิมพ์ พิมพ์จำนวนแล้ว Enter อีกครั้งเพื่อบันทึก
- จำนวนเริ่มต้น 1 คน เลือกจำนวนที่หน้าเดิมก่อนได้ และไม่เกินจำนวนผู้พักคงเหลือ
- RO เปิดหน้าต่างรับชำระเงินตามเดิม เลือกจำนวน ยอด วิธีชำระ และยืนยันรับเงินก่อนบันทึก
- ยกเลิกหรือ Esc ปิดหน้าต่างทั้ง RB/RO โดยไม่บันทึก
- กรอกครบ 4 หลักอย่างเดียวแสดงข้อมูล ยังไม่บันทึก
- บันทึกสำเร็จล้างเลขห้องและคืนโฟกัสให้พิมพ์ห้องถัดไป
อัปเดตออนไลน์หนึ่งครั้งแล้วปิดแท็บแอปทั้งหมด เปิด URL เดิมใหม่เพื่อรับไฟล์ออฟไลน์รุ่นใหม่ ข้อมูลเดิมไม่ต้องนำเข้าใหม่
